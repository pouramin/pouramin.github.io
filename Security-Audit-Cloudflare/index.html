03 / ORIGINAL PROMPTS

Run 1 — Plain CodexREAD-ONLY · SOURCE REVIEW
Perform a thorough, READ-ONLY security audit of this local codebase.

Focus on server-side authorization, privilege boundaries, and cross-workspace data isolation. Inspect all related source files necessary to understand complete authorization paths.

Rules:
- Do not use any additional security audit skills.
- Do not browse the web or consult CVEs, advisories, issues, changelogs, or newer versions.
- Do not install dependencies, execute target code, or contact any endpoint.
- Do not modify application source files.
- Do not assume a suspicious code pattern is an exploitable vulnerability.
- Inspect relevant guards, validators, services, and other security controls before reaching a conclusion.

Complete the audit rather than stopping after planning.

For every finding, provide:
1. A unique identifier.
2. A precise file and line reference.
3. The affected security boundary.
4. The relevant code path and supporting evidence.
5. Potential impact and necessary assumptions.
6. A clear validation status.
7. Possible reasons the finding could be a false positive.

Separate source-supported findings, unverified hypotheses, and hardening suggestions.

At the end, provide a summary table and clearly state any coverage gaps or validation limitations.

Do not claim that exploitation was demonstrated unless it was actually validated in a suitable isolated environment.
Run 2 — With Cloudflare skillFULL AUDIT REQUESTED · SOURCE-ONLY
$security-audit

Perform a thorough, READ-ONLY security audit of this local codebase.

Focus on server-side authorization, privilege boundaries, and cross-workspace data isolation. Inspect all related source files necessary to understand complete authorization paths.

Use the Cloudflare Security Audit Skill in FULL AUDIT MODE.

Follow its six-phase workflow, including independent verification, coverage tracking, structured findings, and final reporting.

Rules:
- Do not browse the web or consult CVEs, advisories, issues, changelogs, or newer versions.
- Do not import findings or context from previous audit runs.
- Do not modify application source files.
- Do not install dependencies or execute target code.
- Do not contact external or deployed services.
- If proper sandbox controls are unavailable, do not execute the target. Record the validation blocker instead.
- Distinguish source-supported findings, unverified hypotheses, rejected candidates, and hardening recommendations.
- Never claim an exploit was demonstrated without actual bounded validation.

Complete all phases supported by the environment.

Produce the skill's structured findings and reports in an explicitly permitted output directory.

Summarize:
1. Findings and supporting source locations.
2. Validation status for each finding.
3. Independently rejected candidates.
4. Coverage limitations.
5. Elapsed time and measurable resource consumption.
6. Any phases that could not be completed.
